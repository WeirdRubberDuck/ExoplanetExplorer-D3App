# Configuration

Each dataset has a corresponding JSON configuration file. The file points to the dataset and tells the ExoplanetExplorer how to interpret and present its columns. Keep the configuration and dataset in sync: every column name in the configuration must exist in that dataset.

At the bottom of this page is a complete [example configuration for the ExoplanetExplorer](#example-configuration).

## Change the Configuration

To change the configuration for a dataset, either edit the existing file, or create a new one. Ensure that all column names in the configuration match the dataset, and update the mappings, display settings, and filters as desired.

The chosen configuration file is loaded in the `exoplanet_explorer` profile. To apply a new configuration file, update the profile to point to the new file, or duplicate the existing profile and modify it accordingly.

## Dataset and Column Mapping

The `datafile` value identifies the dataset to load. In the example below, `${MODULE_EXOPLANETEXPLORER}` is a module path variable, and the CSV is stored in that module's `data` directory.

The `data_mapping` section connects fields that have a specific role in the explorer to column names in the dataset. The left side is the field the explorer expects; the right side is the matching column in the CSV. For example, the explorer's right-ascension position comes from the `ra` column, and the planet name comes from `pl_name`:

```json
"data_mapping": {
    "position_ra": "ra",
    "position_dec": "dec",
    "position_distance": "sy_dist",
    "name": "pl_name"
}
```

Update these mappings whenever a dataset uses different column names. The same applies to the column references in the other configuration sections.

## Display and Filters

The remaining sections configure what information is shown and which presets are available:

- `system_view` lists the columns to show in the details for a system, its stars, and its planets. Use the actual dataset column names in each list.
- `default_colormapping` selects the column used for coloring when the dataset first loads, along with the minimum and maximum values for its scale. In the example, `pl_rade` (planet radius) is mapped from 0.276 to 20.
- `column_info` provides display metadata for columns. For example, `name` sets a readable label, `desc` adds a description, and `format` controls numeric precision. Mark categorical or string columns with `isText: true` so they are treated as text rather than numeric values.
- `quick_filters` defines named preset filters, arranged in groups. Each condition names a dataset column and a `query`; a filter can use one condition or an array of conditions. The group's `type` determines whether its presets are combined with `AND` or `OR`, while `per_line` controls how many presets appear on each line. For example, the planet-bin presets use radius ranges to separate planets into size categories.

When adding a dataset, create or select its configuration and check that `datafile`, every mapped or displayed column, the default color range, and all filter queries match the dataset. A configuration that refers to missing or differently named columns may leave parts of the explorer without the intended data.
